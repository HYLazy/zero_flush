# ZeroFlush vs 原生 RocksDB 性能矩阵（fillrandom + readrandom）

参数：16 线程、key 16B、compression=none、cache 512MB、max_background_jobs=24、subcompactions=16；
ZF：sampled 路由 + base_merge + value_cache 64MB。workload = 所有线程写入数据总和
（num = GB/(16B+value)，16 线程均分）。readrandom = fill 后独立进程 100 万读/线程
（随机写覆盖后命中率期望 63.2%）。系统常驻负载 5-45 波动（grafana/prometheus/ceph）。

规模：10GB ≈ 页缓存内（热）、50GB/100GB 超出（磁盘瓶颈）。日期：2026-08-27/29。

## 6. 观察

1. **写（磁盘瓶颈规模 50/100GB）：ZF 差距 1.04-1.39×**——接近原生（历史 1.92×，M4.11 切片 + R57 修复后大幅收窄）；
2. **写（页缓存热 10GB）：固定开销显性放大**（1.3-5.5×，272B 小值最差——每 op 固定开销占比高）；
3. **读：50GB 差距 1.33-1.85×**（布隆优化后；10GB 热读 4-7× 为索引/固定开销上界）；
4. **100GB 读：ZF 反超原生（0.45-0.96×）**——原生 L0→L6 大 compaction 积压下读放大更高，
   ZF 分区文件布局 + 活跃段索引在小页缓存下更稳；
5. **命中率全部 63.1-63.3% = 随机写覆盖期望（1-1/e），无数据丢失**；
6. R57（索引内存计数器竞态 → 128B 大规模爆发/崩溃）已修复，128B 50/100GB 复测通过。
