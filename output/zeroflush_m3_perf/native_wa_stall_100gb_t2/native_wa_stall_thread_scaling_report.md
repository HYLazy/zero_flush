## 5. 结论

1. **写线程 16→2（8 倍范围），memtable stop 始终绝对主导**：停顿占比 94.6% → 93.7% → 91.4% → 89.2%，
   仅缓降 5.4pp；stop 次数几乎不变（2,605/2,595/2,450/2,460）；L0 与 pending-bytes 停顿恒为 0；
2. **吞吐仅降 25%**（13,978 → 10,539 ops/s）而写线程减 8 倍——写线程几乎全程停顿，
   有效写入速率 = 后台 compaction 消费速率（~11-14K ops/s），与写线程数基本无关；
3. **停顿占比的缓降来自停顿间隙的突发写入变慢**：burst 速率随线程数近似线性下降（~90/45/22/11 MB/s），
   burst 越慢 → 同样消费速率下停顿窗口占比越低——趋近 compaction 支撑速率（~10K ops/s）时停顿将消失；
4. **各层写放大与 compaction 规模与线程数无关**（总放大 9.8-10.5×、L0→L1 平均 9.8-10.6 个输入 SST）
   ——由 workload 分布与 LSM 参数决定；
5. 对 ZeroFlush 的意义：原生 fillrandom 100GB 的写停顿 = 单一 memtable 节流阀
   （compaction 消费 < 生产），线程数只是改变写入突发粒度；ZF 的分区 WAL 直装绕开 memtable 出清，
   其停顿结构（若有的话）在更深层。
